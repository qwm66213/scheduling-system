# 预排班页面改造：从 MySQL 迁移到 OpenAPI

## Context

预排班页面原先的数据流：
- 员工信息：从 MySQL `employee_profile` 表获取
- 排班数据：从 MySQL `pre_scheduling` 表获取
- 数据存储：存入 MySQL `pre_scheduling` 表

现在需要改造为：
- 员工信息 + 排班数据：统一从 OpenAPI 获取
- 数据存储：调用 OpenAPI 新增接口

**目的**：统一数据源，不再依赖 MySQL 存储预排班数据。

---

## OpenAPI 接口信息

### 1. 查询预排班数据

**URL**: `POST https://app.emoosearch.com/open-api/v1/data/records/list`

**入参**:
```json
{
  "table_key": "tb_1ea7b2229e96f",
  "page_size": 100,
  "current_page": 1,
  "filters": ["所属门店:eq:930国和店"],
  "sort": "created_at:DESC"
}
```

**返回字段**:
| 字段 | 说明 |
|---|---|
| 标题 | 日期+员工编码 |
| 日期 | 排班日期 |
| 所属门店 | 门店名称 |
| 月份 | 月份 |
| 员工编码 | 员工编码 |
| 姓名 | 员工姓名 |
| 岗位 | 员工岗位 |
| 工作名 | 业务线（前厅/后厨） |
| 上午出勤状态 | 上午出勤状态 |
| 下午出勤状态 | 下午出勤状态 |
| 小时工工时 | 小时工工时 |
| 借调门店 | 借调门店名称 |

### 2. 新增预排班数据

**URL**: `POST https://app.emoosearch.com/open-api/v1/data/records`

**入参**:
```json
{
  "table_key": "tb_1ea7b2229e96f",
  "records": [
    {
      "标题": "2026-05-21GHD000419",
      "日期": "2026-05-21",
      "所属门店": "930国和店",
      "月份": 5,
      "员工编码": "GHD000419",
      "姓名": "马继跃",
      "岗位": "厨师长",
      "工作名": "后厨",
      "上午出勤状态": "√",
      "下午出勤状态": "√",
      "小时工工时": 0,
      "借调门店": ""
    }
  ]
}
```

**标题拼接规则**: `日期 + 员工编码`（如：`2026-05-21GHD000419`）

**唯一性**：标题字段具有唯一性，一天一人一条数据（包含上午和下午出勤状态）

## 改造要点

### 1. 后端 schedule.js 改造

**删除**：
- MySQL 连接池引用
- `employee_profile` 表 JOIN 查询
- `pre_scheduling` 表 CRUD 操作

**新增**：
- OpenAPI 配置（token、userId、tableKey）
- 门店ID到门店名称的映射（复用 staff.js 中的 `STORE_ID_TO_NAME`）
- 调用 OpenAPI 查询接口
- 调用 OpenAPI 新增接口

### 2. 前端 Schedule.vue 改造

**字段映射调整**：
| 原字段 | 新字段 |
|---|---|
| `business_line` | `工作名` |
| `employment_status` | 移除（不再筛选在职状态） |
| `secondment_status` | 移除（不再显示借调标签） |

**数据结构调整**：
- 移除 `loadStaff()` 单独调用
- 合并为一个接口获取全部数据
- 出勤状态分为上午/下午两个字段

### 3. 数据存储逻辑

**原先**：按 `employee_id + date + period` 存储每条记录

**现在**：按 `日期 + 员工编码` 生成一条记录，包含上午/下午出勤状态

### Step 2: 前端 - 改造 Schedule.vue

**数据结构调整**：
```javascript

// 现在：一条记录（包含上午和下午）

// 原先字段
{
  employee_id, date, period, status, secondment_store,
  name, position, business_line, employment_status
}

// 新字段
{
  日期, 所属门店, 月份, 员工编码, 姓名, 岗位, 工作名,
  上午出勤状态, 下午出勤状态, 小时工工时, 借调门店

```

**字段映射**：
| 原字段 | 新字段 |
|---|---|
| `employee_id` | `员工编码` |
| `name` | `姓名` |
| `position` | `岗位` |
| `business_line` | `工作名` |
| `date` | `日期` |
| `period: 'am'` + `status` | `上午出勤状态` |
| `period: 'pm'` + `status` | `下午出勤状态` |
| `secondment_store` | `借调门店` |

**移除**：
- `employment_status` 筛选（不再判断在职状态）
- `secondment_status` 显示（不再显示借调标签）
- `loadStaff()` 单独调用（合并到 loadAttendance）

**调整**：
- `getCellKey()` 改为按 `日期 + 员工编码` 生成
- `getCellStatus()` 改为读取 `上午出勤状态` / `下午出勤状态`
- `selectStatus()` 改为同时更新上午/下午状态
